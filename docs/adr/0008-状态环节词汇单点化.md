# ADR-0008：状态/环节词汇单点化，UI 只消费 case-state

- 状态：已采纳（2026-10-17）
- 关联：`src/lib/case-state.ts` · `src/lib/validation.ts` · 案例列表/详情 · `review-form`

## 背景

`case-state` 已定义 `CASE_STATUSES` / `STATUS_LABELS` / `REVIEW_STAGES` / `GRADES`，但 UI 与校验层仍在复制词汇：案例库筛选下拉手写四个中文选项；详情页手写 status→stage 三元映射与「初审/终审」；审核表单手写 `['A','B','C']`；校验 schema 另抄一份等级与环节枚举。新增状态、环节或等级时，这些副本会静默漂移。

## 决策

1. 环节标签 `STAGE_LABELS` 与逆向映射 `stageForStatus` 收进 `case-state`；`stageForStatus` 由 `EXPECTED_STATUS` 反查，不维护第二份映射。
2. UI 只消费 `case-state` 的常量与函数：筛选下拉用 `CASE_STATUSES + STATUS_LABELS`，详情页用 `stageForStatus + STAGE_LABELS`，等级选项用 `GRADES`——不再手写标签、枚举数组或三元逆向。
3. 校验层用 `z.enum(GRADES)` / `z.enum(REVIEW_STAGES)` 复用同一枚举；判别联合里的 `z.literal("FIRST" / "FINAL")` 属于结构判别，保留字面量。
4. 状态值的直接比较（如 `status === "REJECTED"`）仍允许：值本身由 `case-state` 定义，UI 只引用、不复制词汇。本 ADR 治理的是标签、逆向映射与枚举清单。

## 后果

- 新增状态/环节/等级时，`case-state` 是唯一改动点；`Record` 类型会让未覆盖的分支在编译期报错。
- 标签与逆向映射不可能与状态机漂移。
- 不引入运行时查表抽象——仍是纯常量与纯函数。
