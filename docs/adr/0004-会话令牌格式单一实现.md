# ADR-0004：会话令牌格式单一实现，auth 与 smoke 双 adapter

- 状态：已采纳（2026-10-14）
- 关联：`src/lib/session-token.ts` · `src/lib/auth.ts` · `scripts/smoke.ts`

## 背景

会话 token 格式（HS256 / 7 天 / cookie 名 `session` / 载荷结构）最初在 auth.ts 与 smoke.ts 各实现一份，靠人工保持同步——会话格式成了带两个实现的隐式 interface。同时守卫的唯一失败形态是 redirect，导致 reviewAction（需返回 FormState）与附件 route（需 401/403）绕开守卫手写检查；`"ADMIN"` 字面量散布 13 处。

## 决策

1. `lib/session-token.ts`（纯 jose，无 server-only/next 依赖）持有 `signSessionToken` / `COOKIE_NAME` / `SESSION_DAYS` / `SessionPayload`——token 格式的唯一实现；auth.ts（httpOnly cookie）与 smoke.ts（HTTP 脚本）是它的两个 adapter，真实复用证明 seam 成立。
2. auth 守卫三件套：`getCurrentUser()`（可空）、`getCurrentAdmin()`（可空，action/route 用）、`requireUser()`/`requireAdmin()`（redirect，页面用）——失败模式是 interface 的一部分，调用方按需选择，不再绕行。
3. `lib/roles.ts` 持有角色唯一合法值清单；getSession 边界校验 role 合法性，登录时 DB 垃圾角色回落 USER（会话角色仅作冗余，实际权限每请求回库读取）。

## 后果

- 改签名算法/有效期/载荷结构只动 session-token.ts，两个 adapter 自动一致。
- 任何文件再出现手搓 `new SignJWT(...)` 或裸 `"ADMIN"` 比较，即违反本 ADR。
