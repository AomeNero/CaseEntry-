# ADR-0005：重复查询形状收敛为查询模块（≥3 次），筛选一律 AND 在可见性之内

- 状态：已采纳（2026-10-14）
- 关联：`src/lib/case-queries.ts` · `src/lib/points-queries.ts` · 各页面

## 背景

积分汇总曾以三种口径分别实现（个人中心 aggregate、首页双榜 groupBy、报表三重 groupBy + 各自手拼用户名 join）——榜单与报表对不上数是真实风险。案例查询的 include/orderBy/可见性知识散布 5+ 个文件。同时注意：全库只有一种存储 adapter（SQLite/Prisma），one adapter = hypothetical seam——这里买的是 locality 与口径一致，不是可替换性。

## 决策

1. 重复 ≥3 次的查询形状才拥有模块：`points-queries`（榜单/单人合计/报表）与 `case-queries`（案例库/详情/动态/队列/分类字典）。一次性查询保持页面内直写（Next 惯用法）。
2. **筛选参数一律 AND 在可见性条件之内**——只收窄、永不放宽，任何调用方（含伪造参数的请求）都无法借筛选越权；不做"仅管理员可用此筛选"的特判。
3. 页面消费查询模块的返回行（prisma 行 + include 关联），UI 映射留在页面。

## 后果

- 榜单/报表口径分歧在结构上不可能；include 变更从 5 处变 1 处。
- 新查询形状出现第 3 个重复时才考虑入模块，克制扩张。
- 若将来更换存储（如 PostgreSQL 之外的第二实现），这些模块是天然的接缝候选——但今天不为此引入任何间接层。
