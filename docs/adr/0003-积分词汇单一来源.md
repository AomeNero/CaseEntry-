# ADR-0003：积分词汇单一来源 points-vocab（纯常量，与发放分离）

- 状态：已采纳（2026-10-14）
- 关联：`src/lib/points-vocab.ts` · `src/lib/points.ts` · `src/lib/validation.ts` · `prisma/seed.ts` · 积分配置表单

## 背景

5 个积分配置键与其标签曾在 6 处独立枚举（case-state、validation、admin 动作、配置表单、个人中心、seed），加等级或事件类型需要 6+ 处联动修改且无编译器帮助；两处 UI 文案把可配置金额硬编码成"+10 分"，管理员一改配置文案即说谎；配置更新为五次非事务 update，缺行时裸抛 P2025。

## 决策

1. `lib/points-vocab.ts` 是积分事件、配置键、标签（事件标签与配置键标签两个维度）、REQUIREMENTS 默认值、`configKeyFor` 的唯一来源。
2. 词汇与发放分离为两个文件：**词汇文件保持纯常量零依赖**（无 server-only / 无 IO），因为它的消费方包括 client 组件与 seed 脚本——这不是可选的洁癖，是物理约束；发放（awardPoints，事务注入 + 幂等）留在 points.ts。
3. zod 校验的键枚举从 `POINT_CONFIG_KEYS` 派生；页面积分文案从 `getPointConfigValues()` 实时读取。
4. 配置更新为单事务 upsert（原子，缺行自动补齐）。

## 后果

- 加等级（A–D）或新积分事件 = 词汇文件一处改动 + 派生物自动跟进。
- 管理员改配置后，所有界面文案立即 truthful。
- 违反本 ADR 的信号：任何文件再出现手写的 `"SUBMIT" | "FIRST_PASS" | …` 键列表。
