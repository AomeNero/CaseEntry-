# ADR-0002：可见性策略单点定义，案例库 = 已入库 ∪ 本人案例

- 状态：已采纳（2026-10-14）
- 关联：`src/lib/case-visibility.ts` · 案例详情页 · 附件 route · 案例库页

## 背景

「已入库全员可见；过程态仅录入人本人 + 管理员可见」这条规则曾以三种错误形态写了三遍：详情页 404、附件 route 403、列表查询 where。任何新表面（导出、API route）都必须记得重新实现它，漏一处即越权。

## 决策

1. `canView(viewer, kase)` 与 `visibilityWhere(viewer)` 是策略唯一来源；各表面自选错误形态（404 / 403 / 查询过滤），规则本体只存一份。
2. 案例库列表同样接入 `visibilityWhere`：普通用户看到 已入库 ∪ 本人全部案例（2026-10-14 确认的行为变化，REQUIREMENTS 可见性条款的字面落地；此前对本人隐藏过程态案例是实现副作用而非产品意图）。

## 后果

- 新表面无法"忘了"这条规则——判定或查询条件总要从这里取。
- 若未来收紧/放宽可见性（例如"驳回案例对管理员隐藏"），只改本模块并跑对应测试。
- 错误形态差异是有意的：详情页用 404（不泄露存在性），附件 route 用 401/403，列表用过滤。
