# Spec: 全站 UI 重设计——Seline 设计语言

**Status:** ready-for-agent

> 来源：grilling 会话共识（两轮全部按推荐执行）。风格规范唯一来源 `DESIGN.md`（Seline Style Reference）；领域词汇见 `CONTEXT.md`。

## Problem Statement

CaseEntry 当前的界面是一套紫色主色 + navy 深色系 + 粉彩状态徽章的视觉体系，与已定稿的 `DESIGN.md`（Seline：暖石画布、单一青色、克制的编辑风）完全脱节。用户面对的是两个问题：

1. 视觉气质与产品定位不符——一个强调「公正审核、积分可信」的内部工具，看起来像营销页，状态色（绿/紫/红粉彩）喧宾夺主，审核工作流的视觉主次（通过 vs 驳回 vs 破坏性操作）没有层次。
2. 全站没有统一的设计语言落地物——页面各自手写样式，没有可对照的规范检查表，后续任何新页面都会继续发散。

## Solution

按 `DESIGN.md` 的 Seline 设计语言对全部 13 个现有页面做纯视觉换血，并新增 404 页（第 14 页）。暖石画布 `#fafaf9` + 纯白卡片 + 1px 细边框成为全站结构；青色 `#3ba6f1` 成为唯一色相；Inter Tight/Inter 双字体体系；审核工作流靠「青色实心（通过）/ 墨黑描边（驳回）/ 墨黑实心 + 二次确认（破坏性）」建立主次。全程不新增任何依赖、不改任何功能与路由。

## User Stories

1. As a 录入人，I want 打开任何页面都看到统一的暖石画布与白卡片视觉，so that 系统感觉是一个整体而不是拼凑的页面。
2. As a 录入人，I want 首页以积分总榜和本月榜为主角呈现，so that 我一眼能看到攒分的目标和自己的位置。
3. As a 录入人，I want 首页有一句克制的标语开场，so that 我明白这个系统「简单录入、公正定级」的定位。
4. As a 录入人，I want 案例状态（待初审/待终审/已入库/已驳回）用形状与灰阶深浅区分而不用红绿紫，so that 界面安静且状态依然可辨。
5. As a 录入人，I want 被驳回的案例有清晰的视觉标记与驳回理由呈现，so that 我知道该改什么、改完交给哪个环节。
6. As a 录入人，I want 表单错误提示醒目但不用红色，so that 全站保持单色纪律且错误依然可见。
7. As a 管理员，I want 审核队列里「通过」是青色实心按钮、「驳回」是墨黑描边按钮，so that 两个动作的主次一眼可辨，不会误点。
8. As a 管理员，I want 删除分类、禁用账号前弹出二次确认，so that 不可逆操作不会被误触。
9. As a 管理员，I want 顶栏的五个管理入口收进一个「管理」下拉，so that 导航清爽，普通用户不受管理链接干扰。
10. As a 匿名访客，I want 登录/注册页是暖石画布上的居中白卡片而非深色全屏，so that 第一眼就建立对系统视觉气质的预期。
11. As a 匿名访客，I want 访问不存在的路径时看到风格一致的 404 页，so that 迷路时也有回家的链接。
12. As a 录入人，I want 标题用 Inter Tight 的 whisper 字重（400）呈现，so that 界面有「安静的权威感」而不是 SaaS 喊叫。
13. As a 管理员，I want 账号表格、积分报表用细线分隔的编辑风表格，so that 密集数据依然易读。
14. As a 录入人，I want 我的案例与个人中心的积分流水以细线列表呈现，so that 我能安静地核对自己的攒分记录。
15. As a 管理员，I want 积分配置表单沿用统一的输入控件风格，so that 后台五个页面与用户侧气质一致。
16. As a 后续开发者，I want 一篇 ADR 记录「全站单色纪律」的权衡，so that 将来不会有人好心地把驳回改回红色。
17. As a 后续开发者，I want 逐页截图走查清单作为验收工件，so that 视觉回归有据可查。

## Implementation Decisions

- **纯视觉层重设计**：路由、页面结构、查询逻辑、server action 零变动；不引入任何新依赖（无 clsx/radix/cva），组件变体保持字符串映射风格。
- **Token 换血采用 expand–contract**：先在全局主题层新增 Seline 全套 token（旧 token 并存不破坏），各页面批次迁移到新 token，最后删除旧 token 与失去用途的旧变体。token 命名与取值照抄 `DESIGN.md` 的 Tailwind v4 `@theme` 清单。
- **单色纪律（立 ADR-0006）**：全站唯一色相为青色三调（cyan-signal / cyan-edge / sky-wash）+ 石色灰阶 + 墨黑/煤黑；驳回不用红、表单错误不用红、破坏性按钮不用红。状态徽章四态与等级 A/B/C 用填充/描边/深浅组合区分。
- **字体**：Inter Tight（展示/标题，weight 400、负字距）+ Inter（正文 14px、行高 1.64），沿用现有 Google 字体加载机制；Roobert 为商业字体不可用。
- **标题体系**：页面标题 32px heading-sm、区块/卡片小标题 20px subheading；青色高亮短语（青字 + 天青药丸底）仅允许出现在首页 hero 与 404 页，每处至多一个。
- **按钮体系**：药丸形；青色实心 = 页面唯一 chromatic 元素且至多一个视口主行动；墨黑描边 = 驳回等次级动作；墨黑实心 + 原生 confirm 二次确认 = 删除分类/禁用账号等不可逆操作。
- **首页**：工作台定位——克制 hero（32px 标题 + 一句副题 + 一处高亮）→ 双榜两列卡片（总榜/本月榜 TOP10，各页主角位）→ 最近入库列表；hero 文案在截图评审时定稿。
- **导航**：普通用户 4 链接 + 管理员入口收进「管理」下拉（导航本就是 client 组件）；右侧保留用户名/管理员徽章/退出；logo 改为小线条火花 + CaseEntry 字标；无吉祥物。
- **登录/注册**：深色全屏改为暖石画布 + 居中白卡片。
- **桌面优先**：维持 flex-wrap 换行式响应，不引入汉堡菜单。
- **smoke 文案锚点逐字保护**：`登录 CaseEntry`、`注册 CaseEntry`、`本月积分榜`、`积分流水`、`通过初审`、`待初审`、`修改后重新提交`、`提为管理员`、`合计` 等全部现有断言文案不可改名。
- **因换肤失去用途的旧变体**（如深色底专用的 on-dark）随 contract 阶段删除。

## Testing Decisions

- **好测试只测外部行为**：本任务是纯视觉改动，「行为未变」由现有测试网证明，「变好看了」由人工走查证明。
- **smoke（HTTP 冒烟）是主力回归接缝**：现有全部断言（文案锚点、状态码、重定向、可见性规则）在每个票完成后必须全绿；它恰好只断言内容不断言样式，天然适配视觉重设计。
- **vitest 既有测试照跑**：重设计零触碰领域层（案例状态机/可见性/积分词汇等模块不动），现有测试即未破坏证明，不新增。
- **唯一新增接缝：逐页截图走查**——dev server 起服，14 页逐页截图对照 `DESIGN.md` Do/Don't 清单；执行者先自检再交用户过目。新增的二次确认行为也归入此走查（冒烟不覆盖 client 交互，沿用现状边界）。
- **不建组件测试接缝**：项目无组件测试基建，为纯视觉重设计引入不值得；接缝越少越好。
- 先例：仓库现有验证文化 = 纯函数表驱动 + test.db 集成 + HTTP 冒烟兜底页面与鉴权路径。

## Out of Scope

- 暗色模式（DESIGN.md 仅定义 light，现状亦无）
- 移动端体验重构（无汉堡菜单，维持换行式响应）
- pricing / blog 等营销页结构的搬用（只取设计语言）
- 任何功能、路由、查询、权限逻辑变动
- 组件测试基建、视觉回归自动化
- 吉祥物/插画人物
- 与 my/profile 页面合并相关的信息架构调整（现维持两页）

## Further Notes

- 实施节奏：地基（token/字体/组件）→ 逐页批次 → contract 清算 + 全站走查；每步四件套（lint/typecheck/vitest/smoke）全绿再进下一步。
- 逐页截图走查清单将在拆票后作为各票验收项出现；hero 文案等细节在走查评审时可否决。
- 风格争议一律回溯 `DESIGN.md` 原文；本文与 `DESIGN.md` 冲突时以 `DESIGN.md` 为准。
