# ADR-0006：全站单色纪律——状态与危险不用红绿，青色是唯一色相

- 状态：已采纳（2026-10-15）
- 关联：`DESIGN.md`（Seline Style Reference）· `src/app/globals.css` · `src/components/badges.tsx`

## 背景

UI 重设计采纳 Seline 设计语言（见 `.scratch/ui-redesign-seline/spec.md`）：暖石画布上以单一青色为唯一 chromatic 声音。但审核域天然需要区分 待初审/待终审/已入库/已驳回 四态与 A/B/C 等级，旧实现用黄/蓝/绿/红粉彩 + 紫/蓝/绿等级徽章表达——正面违反「不得引入绿/紫/红」的设计禁令。表单错误文案（红）与破坏性按钮（红）同样与纪律冲突。

## 决策

1. **全站唯一色相为青**：只允许 cyan-signal `#3ba6f1` / cyan-edge `#3398e1` / sky-wash `#c1e1f7` 三个蓝调 + 石色灰阶 + 墨黑/煤黑。不新增任何色相；绿、紫、红永久出局。
2. **状态靠形状与灰阶区分，不靠颜色**：过程态用青调、入库用墨黑实心、驳回用灰阶描边，等级 A/B/C 用墨黑深浅——可辨识性由填充/描边/深浅组合承担。
3. **红色职能的替代方案**：表单错误文案 = 暖灰/墨黑加粗；破坏性操作（删除分类、禁用账号）= 墨黑实心按钮 + 原生 `confirm()` 二次确认——误触防护从「颜色警示」转移到「确认交互」。
4. **视觉主次承担行为引导**：通过=青色实心（页面唯一 chromatic 元素）、驳回=墨黑描边、破坏性=墨黑实心，主次即安全性。

## 后果

- 驳回失去红色警示，辨识成本转移到描边样式与文案——接受此代价换取全站的编辑级克制。
- 新增色相前必须先修订本 ADR 与 `DESIGN.md`，不允许页面私自引入。
- 「这是错误/危险，为什么不是红色」将成为常见疑问，本文即答案。
